# 3050 example — LoRA fine-tune of Qwen2.5-Coder-0.5B in 84 seconds

A reproducible end-to-end run on a **single RTX 3050 (8 GB, Ampere, sm_86,
native bf16)**. Trains a r=16 LoRA adapter on top of `Qwen/Qwen2.5-Coder-0.5B`
(the **Base** model — not Instruct) using the 16-pair built-in instruction
set, repeated up to 320 examples. No HF download required beyond the base
weights (~954 MB, cached after first run).

## TL;DR

```bash
cd coder-finetune
.venv/bin/pip install -r requirements.txt          # one-time
CUDA_VISIBLE_DEVICES=0 .venv/bin/python train.py --config configs/lora_3050.yaml
.venv/bin/python infer/generate.py --model out/lora_3050/final \
    --prompt-style raw \
    --prompt 'def gcd(a, b):
    """Return the greatest common divisor of a and b."""
' --max-new-tokens 60
```

## Sample completions

The LoRA was trained on raw Python completions wrapped in
`{prompt: "Write a function ...", response: "```python ... ```"}` ChatML
turns. The base model is the **Base** variant (not Instruct), so use
`--prompt-style raw` for direct continuation. ChatML prompting on a
non-instruct base is unstable regardless of the LoRA — that's a property
of the base, not the adapter.

### `def fizzbuzz(n):`

```python
    out = []
    for i in range(1, n + 1):
        s = ''
        if i % 3 == 0: s += 'Fizz'
        if i % 5 == 0: s += 'Buzz'
        out.append(s or str(i))
    return out
```

### `def is_palindrome(s):`

```python
    t = ''.join(c.lower() for c in s if c.isalnum())
    return t == t[::-1]
```

### `def chunks(xs, n):`

```python
    for i in range(0, len(xs), n):
        yield xs[i:i+n]
```

All three exactly reproduce the canonical answers in
[`cf_data/__init__.py`](../cf_data/__init__.py) — expected at this dataset
size (the LoRA is essentially memorizing the small training set), and
useful as a sanity check that the whole training+inference pipeline works
end-to-end.

## What this teaches vs. doesn't

**Teaches:**
- The full LoRA plumbing: `transformers` + `peft` + `trl.SFTTrainer` on a
  consumer GPU — base model load, adapter injection, ChatML formatting,
  cosine LR + warmup, gradient accumulation, adapter-only save.
- Real VRAM/wall-clock numbers on a 3050 you can verify with `nvidia-smi`.
- That an 8.8 M-param adapter (1.75 % of the base) is enough to cleanly
  memorize 320 short instruction-following examples in 80 steps.

**Doesn't teach:**
- Generalization. The dataset is 16 unique pairs; any "performance" you see
  is overfit. To get a useful coder fine-tune you want at least 10k+ varied
  pairs (see `configs/lora.yaml` for the Magicoder-OSS-Instruct-75K recipe).
- ChatML following on a Base model. For natural multi-turn behavior switch
  the base to `Qwen/Qwen2.5-Coder-0.5B-Instruct` (or larger Instruct variants)
  and the same `lora_3050.yaml` recipe will work.

## Reproducing

```bash
cd coder-finetune
rm -rf out/lora_3050
CUDA_VISIBLE_DEVICES=0 .venv/bin/python train.py --config configs/lora_3050.yaml
```

Drop-in alternatives to try:
- `--prompt-style chat` once you switch to an Instruct base.
- `model.name: Qwen/Qwen2.5-Coder-1.5B` in the config — bumps VRAM to ~4 GB,
  still under 8 GB at this LoRA rank.
- `dataset.source: hf` + `dataset.hf_name: ise-uiuc/Magicoder-OSS-Instruct-75K`
  with `max_examples: 5000` — still fits on 3050, takes ~25 minutes.
