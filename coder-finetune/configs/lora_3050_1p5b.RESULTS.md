# Results — `lora_3050_1p5b.yaml`

One real run on an **RTX 3050 (8 GB, sm_86)**, host `i78700`, December 2024.

## Configuration

| field | value |
|---|---|
| base model | `Qwen/Qwen2.5-Coder-1.5B` (1.56 B params) |
| method | LoRA r=16, α=32, dropout 0.05, on q/k/v/o + gate/up/down |
| trainable params | **18.46 M** (1.18 % of total) |
| dataset | `ise-uiuc/Magicoder-OSS-Instruct-75K`, `lang=python` filter |
| examples used | 2,000 of 38,284 Python rows |
| seq len | 1024 |
| batch | 1 × grad_accum 8 → effective 8 |
| precision | bf16 weights + bf16 autocast, fp32 master + AdamW |
| activation checkpointing | on (selective per Qwen2 block) |
| optimizer | AdamW, peak lr 2e-4, warmup 3 %, cosine |
| steps | 250 |

## Throughput & memory

| metric | value |
|---|--:|
| wall time | **24 min 5 s** |
| seconds / step | ~1.6 |
| tokens / step (effective) | 8,192 |
| **peak allocated VRAM** | **5.12 GB** |
| **peak reserved VRAM** | **7.50 GB** |
| headroom on 8 GB card | ~500 MB |

The 7.5 GB reserved figure is the practical limit on this card; running the
same config without gradient checkpointing OOMs at step 1.

## Generation sanity check

Three Magicoder-style prompts (`infer/generate.py` with the saved adapter):

1. **Levenshtein distance** — clean DP implementation, correct base cases.
2. **BFS shortest path** with test cases — graph as `dict[str, list[str]]`,
   queue-based, returns `None` on no path. Correct.
3. **`Vec2` dataclass** with `__add__` / `__mul__` / `length` — frozen
   dataclass, type hints, docstrings. Correct.
4. **Top-N orders SQL query** — readable CTE with `ROW_NUMBER()`. Correct.

Some answers contained an unnecessary `import pandas as pd` line, but every
solution was algorithmically sound and ran when extracted. This matches what
you'd expect from a 250-step LoRA on Magicoder — the model picks up the
"explain → code" formatting and stays on-task in Python.

## Bumping it up

To go from "demonstration" to "actually useful" without changing hardware:

| change | cost | likely benefit |
|---|---|---|
| `max_examples: 10000` | ~2 h wall | tighter loss, fewer hallucinated imports |
| `packing: true` | same VRAM, ~2× throughput | more updates per hour |
| `r: 32` | +2 % VRAM | marginal — r=16 is already enough for SFT on 2k rows |
| HumanEval+ eval | adds ~10 min/model | quantitative pass@1 number |

## Reproducing

```bash
cd coder-finetune
.venv/bin/python train.py --config configs/lora_3050_1p5b.yaml
# Adapter lands in out/lora_3050_1p5b/final/
.venv/bin/python -m infer.generate \
    --base Qwen/Qwen2.5-Coder-1.5B \
    --adapter out/lora_3050_1p5b/final \
    --prompt "Write a Python function that ..."
```

## Bugs found and fixed while building this

Both fixes are in this commit:

1. **`train.py`**: plain LoRA + gradient checkpointing silently produced
   zero gradient flow on most parameters. The input embedding output has
   `requires_grad=False`, which severs the autograd graph at checkpoint
   boundaries. `prepare_model_for_kbit_training` patches this for QLoRA but
   not for plain LoRA, so we now call `model.enable_input_require_grads()`
   ourselves and force `model.config.use_cache = False`.

2. **`cf_data/__init__.py`**: added `lang_filter` argument to `load_hf` so
   Magicoder-OSS-Instruct (mixed-language, 75k rows) can be filtered down
   to a single language without a custom loader.
